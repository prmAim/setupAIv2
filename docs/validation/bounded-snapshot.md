# Synthetic snapshot evaluation

This is a standalone synthetic case, not a score, a Codex mode, or a production sandbox. Run from the repository root with Git, Python 3.13+, and a trusted local Docker daemon. No login, API key, image build, download, solver binary or external repository is needed. Use an operator-owned temp directory, repository/object database and runner image; hostile concurrent host writers are outside this boundary.

```powershell
uv run --offline --locked --isolated python tools/synthetic_evaluation.py
uv run --offline --locked --isolated python -m unittest discover -s tests -v
```

The first command emits one JSON result. Expect `outside_edit: rejected`, `marker_disclosed: false`, zero solver subprocess attempts and `runner.verdict: pass` with an inspected container ID. Missing Docker or local `node:22.23.5-bookworm` means `not_run` and a nonzero exit, not a host fallback. Other errors abort. The runner mounts only staged files, read-only, on network `none`; its fixed Node assertion compares bytes without evaluating the replacement. Temporary roots and the case container are removed on normal completion or an exception. The second command also runs the repository's existing conditional integrations.

## Reuse the data boundary

Recorded evidence: [synthetic runner output](bounded-snapshot-run.json). The locked offline full suite reported `Ran 116 tests in 151.922s`, `OK`. Both exact serialized requests were checked for the sibling marker before dispatch; the negative issue intentionally names the sibling. Only `UnapprovedPath` for that sibling counts as the expected denial. Cleanup also runs on a partial Docker start, checks ownership by unique name and labels before removal, and verifies absence; an unsuccessful cleanup or verification raises instead of reporting a pass.

Each serialized request and proposal has an independent 131072-byte wire limit, including JSON syntax, hashes, whitespace and escapes. The decoded staged result instead permits 16384 UTF-8 bytes per file and 65536 bytes across **all** files (including unchanged ones). A full-size text snapshot may exceed the wire cap when escaped; a compact proposal can fit on the wire but exceed the staged budget. Neither limit substitutes for the other.

1. The trusted caller supplies `build(repo, full_tree_oid, approved, issue)`. `approved` maps exact source paths to SHA-256 of bytes reviewed for disclosure. Do not generate this policy from issue text or auto-approve files by extension. Review the issue text for disclosure too. Unselected sibling names are checked for filesystem ambiguities but their blobs are not opened. Worktree files, commit parents and history are not used.
2. Send only `bundle.request()` bytes to the trusted transport. Input limits: 4 KiB issue, up to eight files, 16 KiB/file, 64 KiB total file content and 64 KiB per traversed Git tree. Only simple lowercase ASCII source paths, bounded depth and mode `100644` are admitted. The canonical JSON contains sorted paths, UTF-8 text and content digests; no root, repository ID or policy object.
3. Accept only JSON bytes: `{request, edits:[{path, sha256, text}]}`. `request` binds the exact input bytes; `sha256` binds the original blob. No command, diff parser, file creation, deletion or rename. `with staged(bundle, response) as root:` yields a new disposable tree only after the entire bounded batch passes and is written. Nothing edits the baseline. Do not deserialize an untrusted Bundle or substitute a caller-supplied staging directory.

The trusted mock runs in-process with no tool dispatcher. Its audit counter measures process-launch events during the solver call only: Git projection and Docker grading are trusted operations outside that window. This is not confinement for arbitrary Python, proof about a real model, or permission to run a golden task.
